⚙ Руководство по разработке плагинов

Архитектура KIP построена на code-first подходе с использованием легковесного SDK. Каждый плагин — это автономный модуль Python, который автоматически регистрирует свои методы и интерфейс в системе.

1. Базовая структура плагина

Создайте новый файл (например, my_plugin.py) в папке plugins/. Минимальный рабочий шаблон:

from core.sdk import BasePlugin, action

class MyCustomPlugin(BasePlugin):
    INFO = {
        "id": "MyCustomPlugin",
        "name": "Мой плагин",
        "version": "1.0.0",
        "author": "Kip",
        "description": "Описание вашего плагина"
    }

    @action(name="hello_action", label="Сказать привет", widget="button")
    def hello_action(self):
        print("Привет из плагина!")
        return "OK"

2. Все типы поддерживаемых виджетов

В параметре widget декоратора @action можно указать один из встроенных компонентов интерфейса:

  • "button" — Обычная интерактивная кнопка действия.
  • "buttons-group" — Панель из нескольких кнопок внутри одной функции (через props).
  • "slider" — Ползунок для числовых значений (громкость, яркость).
  • "select" — Выпадающий список вариантов (выбор профиля, игры или режима).

3. Примеры продвинутых виджетов

Рассмотрим реализацию сложных компонентов, которые мы используем в системных плагинах:

Кнопка:

    @action(
            name="название", 
            label="Отображаемое название", 
            widget="button"
    )
    def hello_action(self):
        # Ваш код
        return "OK"

Панель кнопок (buttons-group):

    @action(
        name="название",
        label="Отображаемое название",
        widget="buttons-group",
        props={
            "buttons": [
                {"label": "Текст на кнопке", "value": "значение для передачи в метод"},
                {"label": "Еще кнопка", "value": "другое значение"},
                {"label": "И так далее сколько угодно", "value": "тут не забываем значение"}
            ]
        }
    )
    def media_control(self, value: str = "значение для привязки кнопки"):
        # Ваш код
        return "OK"

Выпадающий список (select):

    @action(
        name="название действия внутри плагина",
        label="Отображаемое название",
        widget="select",
        props={
            "options": [
                {"value": "значение параметра", "label": "Название параметра"},
                {"value": "значение параметра", "label": "Название параметра"},
                # и так далее
            ],
            "default": "тут значение по умолчанию."
        }
    )
    def launch_game(self, value: str = "само значение"):
        # ваш код
        return "OK"

Слайдер (slider):

    @action(
        name="название",
        label="Отображаемое название",
        widget="slider",
        props={"min": 0, "max": 100, "step": 1, "default": 50} # Тут получается работает так: минимальное значение: 0, максимальное: 100, шаг: 1, и значение по умолчанию: 50
    )
    def set_volume(self, value: str = "Указываем значение по умолчанию"):
        vol_level = int(float(value))
        return f"Значение со слайдера: {vol_level}."

В общем если говорить коротко, то виджеты имеют почти одинаковую структуру, отличие только в параметрах и поведении. Важно еще сказать, что Kip работает тут только как мост между плагинами и пользовательским интерфейсом и свою задачу он старается выполнять, ну а вам надо просто реализовать логику внутри плагина — всю рутину по рендерингу и пробросу событий система берет на себя.

💡 Важные советы разработчикам

• Автозагрузка: Все файлы плагинов сканируются динамически при старте.
• Горячая перезагрузка: После правок кода вызывайте эндпоинт /api/reload.
• Изоляция: Ошибки в плагинах перехватываются бэкендом и не валят приложение.
